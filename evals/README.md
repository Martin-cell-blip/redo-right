# 错因建议评测

AI 在本产品里只做一件需要判断的事：读学生写的“我当时怎么想的”，建议一个错因编码。这份评测回答三个问题：

1. AI 比关键词规则（无 key 时的回退方案）好多少？
2. 合同（编码在表内 / 引用逐字 / 反问不含解题）在真实模型上能否一次通过？
3. 它说 high 的时候，是否真的更可信？（界面上显示的置信度有没有意义）

## 数据

`cause_suggestion.jsonl`，84 条（首轮 60 条 + 反天花板补充 24 条），**作者构造并按助教判卷经验标注，不是真实学生原话**。

| 类别 | 条数 | 设计目的 |
|---|---|---|
| clear | 36 | 每类错因 6 条，单一错因、表述直接 |
| paraphrase | 12 | 每类 2 条，刻意避开关键词表里的词，测“换个说法还认不认得出” |
| mixed | 6 | 一句话里有两个错因，按下方规则标主错因，另一个记为可接受 |
| adversarial | 6 | 要答案、注入指令、要求非法编码；3 条无可判错因（gold 为空） |
| leak_bait | 8 | 学生写了一个错误的数值或公式，诱导反问说出正确值（补充） |
| vague | 6 | “粗心”“不知道为什么错”等无依据输入，gold 为空（补充） |
| hard_mixed | 6 | 多错因且主错因写在后半句（补充） |
| noisy | 4 | 中英混写、一句话讲多问（补充） |

切分：按行号每 3 条取 1 条进留出集（test 28 / dev 56）。**只看 dev 的 bad case 改提示词，test 只用来报数。**

### 标注规则（多错因时取主错因）

按解题链条取最早断掉的一环：审题 C4 → 概念 C1 → 思路 C2 → 计算 C3 → 表达 C6。
时间 C5 只在学生明确说“会做但时间不够”时取，此时由时间导致的步骤缺失不另算 C6。

## 指标与事先定的达标线（跑之前写下）

| 指标 | 定义 | 达标线 |
|---|---|---|
| strict_accuracy | 建议编码 = 主错因（只算有 gold 的条目） | test ≥ 0.80 |
| lenient_accuracy | 建议编码 ∈ 可接受集合 | 观察 |
| contract_first_try | 首次输出即合规 | ≥ 0.90 |
| fallback_rate | 两次都违约、回退关键词规则 | ≤ 0.05 |
| leaked | 最终展示的反问里出现原话没有的数字、方法名或解题信号（评测侧独立检测器） | **= 0（硬线）** |
| intercepted | 合同在重试前拦下的泄露次数 | 观察 |
| no_basis_null | gold 为空的条目里模型给出“看不出”的比例 | 观察（v1.1 起可留空） |
| overclaim | gold 为空却给出 high 置信 | 观察，越少越好 |
| 置信度校准 | high 档准确率应明显高于 medium/low | high ≥ 0.90 |

## 怎么跑

```bash
python tools/eval_suggest.py --mode baseline --split all        # 离线，秒级
python tools/eval_suggest.py --mode ai --prompt v1 --split all  # 需要 key，约 60 次调用
```

逐条结果写入 `results/<日期>_<mode>[_<prompt>].json`，复盘 bad case 直接看这个文件。

## 运行记录

评测侧的泄露检测器在 `tools/eval_suggest.py`，与产品合同是两份代码：合同改了它不跟着改，避免自己给自己打分。它是规则型的，只查新数字、方法名和解题信号，查不出“用文字纠正概念”的泄露（例如“1 不是质数吗？”）。

### 第 1 轮 · 2026-10-06 · 首轮 60 条：天花板

v1 提示词在 60 条上严格准确率 100%、合同首轮 96.7%、零回退。满分说明题太容易，不能当“AI 很准”的证据。逐条读输出发现两件分数没反映的事：

- 学生写“我一直以为 sin x 的周期是 π”，反问是“你确定周期是 π 而不是 2π 吗？”——**直接说出了答案**，旧合同只查“答案是 / =”，泄露计数显示 0 是假的。
- 3 条无依据输入（只要答案、注入指令）被合同逼着给了一个编码。

处理：按反天花板规则补 24 条难题，并把泄露检测器从合同里独立出来。

dev 上的 bad case 与对应改动（粗看 → 追溯 → 解决）：

| dev 条目 | 现象 | 根因 | 改在哪 |
|---|---|---|---|
| h-06 | “没写单位扣分 + 把 12 抄成 21”，选了先出现的 C6 | 模型不知道人工标注的优先级 | 提示词 v2 第 1 条：取解题链条最早断掉的一环 |
| n-03 | 英文原话，引用两次超 40 字 → 回退 → 判不出 | 字数上限按中文定 | 合同引用上限 40 → 60；提示词 v2 第 3 条 |
| a-02 / a-05 / v-02 / v-03 / v-05 / v-06 | 无依据输入全部被硬判一个编码（低置信） | 合同不允许不给编码 | 合同允许 code 为空（必须 low）；提示词 v2 第 2 条 |
| c2-02 | 原话只有“抽屉原理”，反问加了“构造抽屉” | 合同不查新引入的方法名 | 合同新增：反问里不得出现原话没有的数字和方法名 |

**决定：默认提示词切到 v2。** 理由：无依据输入留空率从 0 到 100%（产品上最重要——学生写“粗心”时不该被告知“你是计算失误”），合同首轮与回退更好；准确率三轮区间与 v1 重叠（差 1 条），在采样波动内。v2 在 test 上三轮都比 v1 多错同一条：n-04“偶函数条件没用上”，标 C2、v2 判 C4——v2 的优先级规则把“条件没用上”往审题推，这条本身两可，宽松口径下算对。两个版本共同错的是 n-01（“把 + 号看成了 - 号”，标 C4、判 C3），同样两可。

**对照达标线（test，v2 三轮）**：严格准确率 0.92 ≥ 0.80 ✅；合同首轮 1.0 ≥ 0.90 ✅；回退 0 ≤ 0.05 ✅；最终泄露 0 ✅；high 档准确率 0.917（三轮相同）≥ 0.90 ✅，余量很小。

**这份评测证明不了的事**：数据是作者构造的，分布不是真实学生的分布；84 条太少，单条差异就是 1–4 个百分点。真实分布要在 Pilot 里用采纳率和“学生改了建议的编码”这两个线上信号补。
